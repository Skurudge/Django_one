# Мой учебный проект Python "Django_one"

## Описание:

Проект представляет собой развивающийся маркетплейс "Skystore" — платформу для хранения, публикации и продажи плагинов и примеров кода [catalog:views]. Веб-приложение построено на базе фреймворка Django с использованием архитектурного подхода CBV (Class-Based Views), СУБД PostgreSQL и стилизации интерфейса на Bootstrap [catalog:views, config:settings]. В систему интегрирована полноценная ролевая модель доступа (RBAC), модерация контента, контентный раздел (блог) и продвинутые механизмы валидации данных [catalog:forms, catalog:views, blog:views].

Редактирование содержания проекта сторонними пользователями не предусмотрено.

## Установка:

1. Клонируйте репозиторий:
   ```bash
   https://github.com
   ```
2. Настройте переменные окружения в файле `.env` в корне проекта (укажите параметры подключения к PostgreSQL и `SECRET_KEY`) [config:settings].
3. Сгенерируйте и примените миграции базы данных [catalog:models, users:models]:
   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```
4. Автоматически настройте группы пользователей и права доступа согласно ролевой модели [catalog:management:commands:create_groups]:
   ```bash
   python manage.py create_groups
   ```
5. Наполните базу данных тестовыми материалами с автоматической привязкой к системному владельцу [catalog:management:commands:add_products]:
   ```bash
   python manage.py add_products
   ```

## Использование:

1. Запустите локальный сервер разработчика: `python manage.py runserver`.
2. Перейдите по адресу `http://127.0.0` в вашем веб-браузере.
3. Доступ к интерфейсу и кнопкам управления динамически меняется в зависимости от прав и роли авторизованного пользователя [catalog:templates:home, catalog:templates:product_detail, blog:templates:blog:blogpost_list].

### Разработанные объекты, функции и модули:

* **Ролевая модель доступа и права (Задание 1):**
  * В модель продуктов добавлено поле `is_published` для контроля статуса модерации [catalog:models]. Новые товары по умолчанию скрыты от общей витрины (`False`) [catalog:models].
  * Объявлено кастомное право доступа `can_unpublish_product` для управления публикацией продуктов [catalog:models].
  * Разработана кастомная команда `create_groups` для автоматического создания и настройки ролей в системе [catalog:management:commands:create_groups]:
    * **Модератор продуктов:** наделен правами отмены публикации и удаления любого товара [catalog:management:commands:create_groups].
    * **Контент-менеджер (Дополнительное задание):** наделен полными правами на CRUD-операции внутри раздела блога [catalog:management:commands:create_groups].
* **Механизм владения объектами (Задание 2):**
  * Модель продукта связана с моделью пользователя через поле `owner` (`ForeignKey`) [catalog:models].
  * Внедрено автоматическое назначение создателя: при добавлении нового товара поле `owner` заполняется текущим авторизованным пользователем [catalog:views].
  * Реализована строгая проверка на уровне контроллеров: изменять товар может только его прямой владелец или модератор [catalog:views]. Удалять товар разрешено только владельцу либо модераторам из профильного отдела [catalog:views].
* **Динамический интерфейс на основе прав:**
  * Шаблоны каталога и блога адаптированы под проверку прав (`perms` и `owner == user`) [catalog:templates:home, catalog:templates:product_detail, blog:templates:blog:blogpost_list, blog:templates:blog:blogpost_detail]. Кнопки «Редактировать» и «Удалить» выводятся в интерфейсе строго тем ролям, которым они доступны по бизнес-логике [catalog:templates:home, catalog:templates:product_detail, blog:templates:blog:blogpost_list, blog:templates:blog:blogpost_detail].
  * В форме добавления товаров (`ProductForm`) поле публикации автоматически скрывается от обычных пользователей, исключая возможность самомодерации [catalog:forms].
* **Кастомная система аутентификации (Приложение `users`):**
  * Реализована кастомная модель на базе `AbstractUser` с авторизацией по `email` и дополнительными полями (аватар, телефон, страна) [users:models, users:views]. Настроена автоматическая отправка приветственных писем при регистрации [users:views].
* **Продвинутая валидация и защита от спама:**
  * Интегрирована проверка названий и описаний на запрещенные спам-слова без учета регистра с автоматическим приведением названий к нижнему регистру [catalog:forms]. Внедрена валидация против отрицательных цен и жесткое ограничение на загрузку файлов картинок (до 5 МБ, форматы JPEG/PNG) [catalog:forms].

### Тестирование:

* Тестирование ролевой модели выполняется вручную путем последовательной авторизации под аккаунтами с разными ролями (Гость, Обычный пользователь, Модератор продуктов, Контент-менеджер, Суперпользователь) и проверки доступности кнопок и эндпоинтов.
